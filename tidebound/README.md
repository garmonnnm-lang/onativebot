# TIDEBOUND

Браузерная 3D-игра на выживание (Three.js + TypeScript + Vite): рыбалка, добыча ресурсов, крафт, смена суток, штормы.
Одиночная игра и кооператив (комнаты по коду или ссылке).

## Быстрый старт
```
npm install
npm run dev:all      # сервер комнат (порт 3001) + клиент (http://localhost:5173)
```
Только одиночная игра: `npm run dev` (сервер не нужен).
Только сервер: `npm run server`.

Управление (ПК): WASD, Shift, Пробел, ЛКМ, E (взаимодействие), 1–5, Tab (инвентарь), G (крафт; у верстака — расширенный), Esc (пауза).

### Мобильные устройства
Сенсорный режим включается автоматически на телефонах и планшетах (`?touch=1` / `?touch=0` — принудительно):
левая половина экрана — плавающий джойстик, правая — обзор перетаскиванием; кнопки ✋ (действие), ⤒ (прыжок), E, » (бег), ▾ (присесть),
для удочки — ⟲ (смотать) и 🪱 (наживка); сверху — крафт, инвентарь, полный экран, пауза; слоты хотбара нажимаются пальцем.
На мобильных по умолчанию низкое качество графики и без теней (меняется в настройках). Играть лучше в горизонтальной ориентации;
на iPhone добавьте игру на экран «Домой» (Поделиться → На экран «Домой») — откроется без интерфейса Safari.

## Деплой на Render
1. Залейте папку проекта в GitHub-репозиторий (корень репозитория = папка с `package.json`).
2. Render → New → **Blueprint** → выберите репозиторий (подхватится `render.yaml`) → Apply.
   Или вручную: New → Web Service: Build `npm install --include=dev && npm run build`, Start `npm run server`, Health Check Path `/health`.
3. Через пару минут игра откроется по адресу `https://<имя>.onrender.com` — клиент и WebSocket на одном домене (`wss://` включается сам).
Примечания: на free-плане сервис засыпает через 15 минут без трафика (первый заход после сна ~30–60 с), а сохранения комнат
хранятся во временной файловой системе и пропадают при перезапуске. Одиночные сохранения лежат в браузере игрока и не зависят от сервера.

## Кооператив
1. Один игрок: «Создать комнату» → копирует код или ссылку → «Начать игру».
2. Остальные: «Присоединиться к комнате» (код) или «Играть» (список открытых лобби) или переход по ссылке `?room=КОД`.

Архитектура: авторитетный сервер комнат на Node.js (папка `server/`, без внешних зависимостей: собственный WebSocket по RFC 6455).
Общий протокол и проверки — `shared/net.ts`. Сервер решает: состав комнаты и хозяина, допустимость перемещений
(антителепорт), удары по деревьям/камням и награду за них (выдаётся один раз), вскрытие общих тайников,
серверное время и погоду. Состояние комнаты (ресурсы, тайники, время, погода) сохраняется в `server/data/rooms/*.json`
и восстанавливается после перезапуска сервера по тому же коду. Обрыв связи: 45 с на возвращение, клиент переподключается сам.

Переменные окружения сервера: `PORT` (3001), `HOST` (0.0.0.0), `DATA_DIR`, `ALLOWED_ORIGINS` (через запятую; пусто — любые),
`SERVE_DIST` (папка клиента, по умолчанию `dist/`). Клиент: `VITE_SERVER_URL` (по умолчанию в dev — `http://<хост>:3001`,
в production — тот же адрес, откуда загружена страница).

### Один процесс для хостинга
```
npm run build
npm run start        # сервер отдаёт и клиент, и WebSocket на одном порту
```
За HTTPS-прокси (nginx/Caddy) нужно пробросить WebSocket (заголовки Upgrade/Connection) на тот же порт; клиент автоматически
использует `wss://`, если страница открыта по `https://`.

## Что пока не реализовано
- Инвентарь, уровень и рыбалка в кооперативе считаются на клиенте (сервер проверяет только ресурсы, тайники, позиции и время).
- Нет режима строительства, животных, боя, событий, транспорта, чата-окна (сообщения чата принимаются сервером, ввод в UI не добавлен).
- Аватары других игроков — временные процедурные модели.
- Нет сна и сохранений в кооперативе; других игроков нет на миникарте.
